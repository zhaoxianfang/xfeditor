一、总览

xfEditor 在初始化配置对象（xfEditor({ ... })）中以回调函数的形式暴露事件；同时实例也提供一系列方法供运行时调用。所有回调的 this 均指向编辑器实例，可直接调用其 API。

回调统一格式：onXxx: function(arg1, arg2) { /* this === 编辑器实例 */ }。未配置的回调默认为空函数，不会报错。

二、生命周期事件

回调触发时机参数说明
onEditorLoad编辑器（含 CodeMirror）加载完成—适合执行依赖实例就绪的初始化逻辑
onload编辑器整体加载完成—最常用入口，可在此操作编辑器实例
onPageLoad当前网页加载完成—页面级资源就绪
onAllAsyncLoad编辑器内所有异步依赖（KaTeX / FlowChart / SequenceDiagram / ECharts 等）加载完成—渲染图表/公式前确保依赖就绪
onPageAllLoad网页所有异步加载完成—
onresize编辑器尺寸变化(width, height)
onfullscreen进入全屏—
onfullscreenExit退出全屏—

回调触发时机参数说明

onkeydown / onkeyup编辑区键盘按下/抬起(cm, event)
onmousedown / onmouseup编辑区鼠标按下/抬起(cm, event)

四、预览相关事件

回调触发时机参数说明
onpreviewing预览渲染开始前—可在渲染前拦截/修改数据源
onpreviewed预览渲染完成后—适合在预览 DOM 上做后置处理（如绑定自定义交互）

同步滚动（编辑区 ⇄ 预览区）

由配置 syncScroll: true 开启，双向精准同步。相关可调用方法：

  • bindSyncScroll() / unbindSyncScroll() — 手动绑定/解绑
  • scrollToLineNum(lineNum, linePercent) — 滚动预览区到指定编辑行
v2.0.0 增强：预览区图片/视频/音频加载完成会自动失效位置映射并重建，避免同步滚动跳转错位；图片缩放、表格编辑等预览交互期间会暂停同步，杜绝抖动与回环。

五、文件上传 / 删除通知 v2.0.0 新增

为避免服务器存储「僵尸文件」，已上传到服务器的文件在编辑器内容中被删除或替换时，会自动通知服务端清理，并触发对应回调。

配置项

配置类型说明
fileDeleteURLString统一删除通知接口（图片/视频/音频/附件共用的兜底地址）
imageDeleteURLString图片删除接口（优先级高于 fileDeleteURL）
videoDeleteURLString视频删除接口（优先级高于 fileDeleteURL）
audioDeleteURLString音频删除接口（优先级高于 fileDeleteURL）
onFileUploadedFunction文件上传成功回调：function(fileInfo)
onFileDeletedFunction文件被移除并通知服务端回调：function(fileInfo)

fileInfo 结构

{
  type: "image" | "video" | "audio" | "file",  // 文件类型
  url:  "https://...",                          // 服务端返回的可访问地址
  name: "example.png"                           // 文件名（可选）
}

触发流程

  1. 通过图片/视频/附件对话框或拖拽/粘贴上传成功 → 自动调用 _trackUploadedFile(info) 登记，并触发 onFileUploaded。
  2. 编辑器内容变化（防抖）时，比对正文引用与已登记文件：曾经出现在正文中、现在消失的文件，判定为被删除/替换。
  3. 调用对应删除接口（POST FormData，字段 url/type/name），并触发 onFileDeleted。
注意：仅服务端返回可用 URL 的文件会被登记；base64 内联图片（离线模式）不会被登记，也不会触发删除通知。已上传但从未插入正文的文件不会被误删。

服务端约定（建议）

// 请求：POST fileDeleteURL
// Content-Type: multipart/form-data
// 字段：url（必填）、type、name
// 响应示例：
{ "success": 1 }

实例方法

方法说明
_trackUploadedFile(info)登记已上传文件（上传成功时自动调用）
_notifyFileDeleted(info)通知服务端删除并触发 onFileDeleted
_syncUploadedFiles()立即比对正文与已登记文件，清理被删除项

5.1 资源语法删除事件（内容变更通知 · 面向开发者）

当用户在编辑区删除 / 替换一条图片、视频、音频或附件语法时（例如删除 ![Logo](../images/logo.png)<180,180> 整行，或把视频链接改为其它地址），编辑器会实时检测并触发对应的“资源删除事件”，把该资源的 url、文件名以及“编辑区是否仍包含该地址”告知开发者。开发者可在回调中做埋点上报、二次确认、联动清理、撤销提示等。

与 5 的区别：第 5 节是「已上传到服务器的文件被删除 → 自动通知服务端清理」；而本小节是「任意资源语法（含未上传的纯引用、站内链接）从正文消失 → 通知开发者」，二者都通过 onFileDeleted 派发，用 event:"delete" 字段区分。

配置项（回调）

回调触发时机
onImageDeleted(info)图片语法（Markdown ![alt](url) 或 HTML <img>）从编辑区消失
onVideoDeleted(info)视频语法（HTML <video> 或 @video / .mp4 链接）从编辑区消失
onAudioDeleted(info)音频语法（HTML <audio> 或 .mp3 链接）从编辑区消失
onFileDeleted(info)附件语法（.pdf/.docx 等文档链接）消失；也用于第 5 节的服务端清理通知

info 结构（资源删除事件）

{
  type      : "image" | "video" | "audio" | "file",  // 资源类型
  url       : "https://.../logo.png",                // 被删除资源的地址
  name      : "logo.png",                            // 从地址中提取的文件名（文件信息）
  stillUsed : true,                                  // 当前编辑区是否【仍】包含该地址（用于区分“真正删除”与“移动/复制后删原处”）
  event     : "delete"                               // 固定值，用于与文件上传成功事件区分
}

检测范围

  • Markdown 图片：![alt](url)
  • HTML 标签：<img src> / <video src> / <audio src> / <source src>
  • Markdown 链接：[text](url)，按扩展名归类（图片/视频/音频/附件）；无扩展名的纯网页链接不会触发，避免误报
提示：程序化替换内容（setValue / setMarkdown / clear / appendMarkdown）会重置检测基线，不会误触发删除事件；初始化加载文档时已建立基线。

5.2 CSRF 防护 v2.0.0 新增

为防止跨站请求伪造（CSRF）攻击，上传（XHR）与删除（通知服务端）请求会自动携带 CSRF 凭证：

  • XHR 上传 / 删除：请求头携带 X-CSRF-TOKEN: <token>；
  • 隐藏 iframe 表单上传：表单内自动注入名为 _token 的隐藏域（字段名可用 csrfFieldName 覆盖）。

Token 读取优先级

settings.csrfToken                                   // ① 显式指定，优先级最高
  → <meta name="csrf-token" content="xxx">           // ② 页面 meta 标签
  → window.csrfToken / window.Laravel.csrfToken        // ③ 全局变量
  → window.XSRF_TOKEN                                  // ④ 备选全局变量

配置项

配置类型说明
csrfTokenString显式指定 CSRF Token；留空则按上述优先级自动读取
csrfFieldNameString隐藏 iframe 表单上传时写入的字段名，默认 _token（Laravel 约定）

接入示例

<!-- 页面中放置 CSRF Token（如 Laravel Blade 模板） -->
<meta name="csrf-token" content="{{ csrf_token() }}">

<script>
var editor = xfEditor({
    id: "edit",
    imageUploadURL : "/api/upload/image",
    fileDeleteURL  : "/api/file/delete",
    // 无需手动传 token：编辑器会自动读取 <meta name="csrf-token">
    // 如需显式指定：csrfToken: "xxxx", csrfFieldName: "_token"
    onImageDeleted: function (info) {
        console.log("图片语法被删除：", info.url, "仍被引用：", info.stillUsed);
    }
});
</script>

七、如何监听与接入

方式一：初始化配置（推荐）

var editor = xfEditor({
    id: "edit",
    path: "../lib/",
    syncScroll: true,

    // 文件上传/删除通知
    imageUploadURL: "/api/upload/image",
    fileDeleteURL:  "/api/file/delete",
    onFileUploaded: function (info) {
        console.log("已上传：", info.type, info.url);
    },
    onFileDeleted: function (info) {
        console.log("已通知服务端删除：", info.url);
        // 可在此增加二次确认或上报
    },

    onchange: function () {
        // 内容变化（预览渲染后）
    },
    onpreviewed: function () {
        // 预览 DOM 就绪，可绑定自定义交互
    }
});

方式二：运行时调用实例方法

editor.on("load", function () { /* 或 onload 回调 */ });
editor.setValue("# 新内容");
editor.scrollToLineNum(12);          // 同步滚动到指定行
editor._syncUploadedFiles();         // 主动触发一次删除比对

方式三：拖拽 / 粘贴自动处理

无需额外代码：拖入或粘贴图片、视频、音频、附件到编辑区时，编辑器会按类型自动识别——配置了上传地址走 XHR 上传并回插对应 Markdown；未配置地址时，图片转为 base64 内联（唯一例外），视频/音频/附件则提示需配置上传接口。

八、注意事项

  • 上传地址门控：视频/音频/附件若未配置对应上传地址，本地上传入口会被禁用，不会在浏览器侧保存文件；仅图片允许在无地址时以 base64 内联。
  • 删除通知时机：在内容编辑触发防抖后比对，正文不再引用即视为删除。已上传但从未插入的文件不会被误删。
  • 跨域上传：开启 crossDomainUpload 时需配合 uploadCallbackURL，删除通知仍走 fileDeleteURL 系列。
  • 性能：大量图片加载会触发位置映射重建（已防抖），建议服务端返回带尺寸的图片以减少回流。
  • this 指向：所有回调内 this 均为编辑器实例，可直接调用 this.getMarkdown() 等方法。
